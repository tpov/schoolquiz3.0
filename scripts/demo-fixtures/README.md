# Демо-фикстуры матрицы Арены (server half 3.3)

Манифест ролей и банков для строк матрицы Арены (план §2 Шаг 4) и рабочие инструменты к
нему. Фикстуры только готовят условия — оцениваемые прохождения, рейтинги, выплаты и
сезонные расчёты выполняет приложение.

## Состав

- **`manifest.json`** — единственный источник истины: бэкенд, роли (закреплённые
  экспорт-era авторы + засеянные куратор/игроки), два банка (цены 1 и 100),
  fixture-owned строки сервера, закреплённые предпосылки, команды засева и проверки.
  Рейтинг каждого банка несёт пин `rating` (`ratingSum`/`ratingCount`/`ratingVersion`)
  и флаг `seeded`: `true` — документ рейтинга fixture-owned (дрейф чинится до пина,
  см. «Дрейф и ремонт»), `false` — закреплённая предпосылка (только сверяется).
- **`seed-demo-fixtures.js`** — идемпотентный засев admin-SDK против эмуляторов
  демо-бэкенда; ноль перезаписей: существующая seeded-фикстура сверяется с манифестом
  и оставляется как есть, отсутствующая — создаётся, расхождение — именованный отказ.
  Закреплённые предпосылки (экспорт-era цепочки ac_* и их авторы) только сверяются.
- **`verify-demo-fixtures.js`** — только чтение: продакшн-юниверс
  `createArenaEligibleUniverse` с продакшн-лоадером контекста обязан держать банки на
  ценах 1 и 100 при любом составе юниверса.
- **`rating-pins.js`** — общая прамбула рейтинговых пинов (ретро item 4b): сверяет
  оба банка с пинами манифеста и чинит дрейф громким логом (merge ровно трёх пиновых
  полей; `authorUid` и прочие поля, как и чужие данные, не трогаются). Вызывается в
  начале `main()` драйверов, трогающих рейтинги, — `arena-races` и `arena-quotas`
  (`arena-online-o2` рейтинги не пишет и прелюдию не вызывает); отдельно — через
  `repair-pin.js`.

## Драйверы

Живые прогоны против demo-backend (эмуляторы 18090/19090, functions-эмулятор хоста
для callables, где прогону он нужен):

- **`arena-races-live-run.js`** — story 3.8: неизменяемость замороженной цены сквозь
  settle, гонка двух попыток за одну мутацию (ровно-один-раз), роялти-консервация;
  window-мутация рейтинга с finally-восстановлением.
- **`arena-quotas-live-run.js`** — story 3.7: concurrency случайных квот и SELECTED
  счётчиков; то же хрупкое окно мутации рейтинга с finally-восстановлением.
- **`arena-online-o2-live-run.js`** — ONLINE-O2 (3.2): открытие окна, повторная выдача
  с тем же deadline, ready-ACK с replay-квитанцией, чужое окно, отсутствие окна после
  последнего вопроса.

Journey-инструменты (снапшоты дерева + живые callables; сами UI-переходы идут из рига):

- **`curator-journey.js`** — 4.8 curator-transitions: снапшоты, замороженная
  попытка-фикстура, живой rating, probe-отказ не-куратора.
- **`inbox-journey.js`** — 4.9 inbox-private-error-reports: снапшоты, живой
  listInboxItems, rules-легальный комментарий-фикстура, replay-проба отчёта.
- **`poll-journey.js`** — 8.2 poll-series-run: снапшоты, живые списки опросов,
  scripted-голос второго/третьего участника, replay ключа мутации.
- **`review-fee-journey.js`** — 4.7: платный цикл проверки — тариф, фонд, carry,
  перепроверка, идемпотентность повторов.
- **`tz06c-journey.js`** — 4.3: снапшоты публичного/приватного дерева, бутстрап
  кураторского профиля, scripted-ревью реальными callables.

Read-only:

- **`arena-quotas-baseline-read.js`** — baseline прогона 3.7 до старта: экономика
  probe-игроков, квотный документ дня, счётчики, RESERVED-тикеты, строки юниверса.
- **`verify-demo-fixtures.js`** — гейт цен (см. выше); обязателен после любого ремонта.

## Дрейф и ремонт

Контейнер демо-бэкенда (`schoolquiz-demo-firebase-20261004`, порты 18090/19090)
может дрейфовать от манифеста: протухший рейтинг банка, отсутствующая seeded-цепочка,
чужие данные игроков. Правила ремонта:

1. Данные игроков и незапиненные документы никогда не перезаписываются. Чинятся
   только fixture-owned пути: три пиновых поля рейтинга каждого банка (merge) и
   отсутствующие seeded-документы (создание по манифесту).
2. Дрейф рейтингов пинов чинит **`repair-pin.js`** (та же логика, что прамбула
   live-run драйверов): совпало — ничего не пишет, расходится/нет — merge трёх полей
   и громкий лог. Идемпотентно.
3. Отсутствующие seeded-цепочки (весь easy-банк `demoarena_easy1_*`, review-строки)
   восстанавливает **`seed-demo-fixtures.js`** (ноль перезаписей: расхождение —
   именованный отказ, а не правка).
4. После ремонта обязан пройти **`verify-demo-fixtures.js`**.

На хосте node нет — запуск в throwaway-контейнере (сеть хоста достаёт эмуляторы на
`127.0.0.1`, репо в `/repo`; контейнер должен быть поднят — не запускать его ради
ремонта, при поднятых эмуляторах):

```sh
docker run --rm --network host -v "$PWD:/repo:rw" -w /repo \
  -e GCLOUD_PROJECT=demo-schoolquiz-mvp \
  -e FIRESTORE_EMULATOR_HOST=127.0.0.1:18090 \
  node:22-bookworm-slim node scripts/demo-fixtures/repair-pin.js

docker run --rm --network host -v "$PWD:/repo:rw" -w /repo \
  -e GCLOUD_PROJECT=demo-schoolquiz-mvp \
  -e FIRESTORE_EMULATOR_HOST=127.0.0.1:18090 \
  -e FIREBASE_AUTH_EMULATOR_HOST=127.0.0.1:19090 \
  node:22-bookworm-slim node scripts/demo-fixtures/seed-demo-fixtures.js

docker run --rm --network host -v "$PWD:/repo:rw" -w /repo \
  -e GCLOUD_PROJECT=demo-schoolquiz-mvp \
  -e FIRESTORE_EMULATOR_HOST=127.0.0.1:18090 \
  node:22-bookworm-slim node scripts/demo-fixtures/verify-demo-fixtures.js
```

Хостовые запуски (если node есть) — те же переменные окружения, хост
параметризуется через `FIRESTORE_EMULATOR_HOST`/`FIREBASE_AUTH_EMULATOR_HOST`;
`GCLOUD_PROJECT=demo-schoolquiz-mvp`, `GOOGLE_APPLICATION_CREDENTIALS` не задан.

## Синтаксис-гейт

Все скрипты каталога покрыты `node --check` в `npm run lint` каталога `scripts/`
(ретро item 4d) — битый драйвер не доезжает до прогона.

Потребители: 3.11 (консервация цен/рейтингов), строки матрицы 3.4–3.10, сезонные
фикстуры 3.12 (отложены туда же, здесь не засеиваются).
