# Fix Spec: Recover Local Build Gate for SCH-2 Implementation

## Problem

### Symptom

Phase-01 implementation changes for SCH-2 are applied and non-Gradle guards pass, but the Gradle build gate never reaches `PASSED`. Mandatory reviewers were not launched because validation is blocked before the feature can be reviewed.

### Reproducer

From the current active workspace:

1. Run `./gradlew :android:feature:local:settings:presentation:compileDebugKotlin --no-configuration-cache`.
2. The task fails in `:buildSrc:compileKotlin`, before settings feature compilation, while Gradle/Kotlin attempts to clean or load build outputs containing AppleDouble `._*` sidecar files.

The app-level validation path is also blocked until the ignored local Android SDK config and ignored Firebase client config are provisioned for this machine.

### Severity

blocker

## Root Cause

### Confirmed / Hypothesized

CONFIRMED: the observed build failure is caused by local build-environment/provisioning blockers, not by SCH-2 UI feature logic.

Confirmed blocker chain:

1. The active workspace is under `/Volumes/EXTERNAL`, whose filesystem is ExFAT; macOS is creating AppleDouble `._*` sidecars in project/build intermediates. Those sidecars are present in Gradle/Kotlin/Android outputs and can break cleanup, resource parsing, and classpath snapshot tasks.
2. `local.properties:8` points to `/home/tpov/Android/Sdk`, which does not exist on this macOS machine; the usable SDK is `/Users/tpov/Library/Android/sdk`.
3. `apps/android-next/google-services.json` is absent. It is intentionally untracked/ignored local config, but app-level Gradle gates expect it.

Phase 2 deep feature-code debugging was intentionally skipped because Phase 1 reproduced the build failure before feature compilation and confirmed the blocker category.

### Why pipeline missed this

Implementation preflight did not validate local build prerequisites before starting feature development: filesystem suitability, AppleDouble contamination, `local.properties` SDK reachability, and ignored app Firebase client config presence. The failure surfaced late at the implementation build gate, after UI/test edits were already applied, so retrospective should add an environment preflight guard before dev/review fan-out.

## Proposed Fix

### Scope

large (cross-environment/provisioning recovery plus full Gradle validation; not a small source-code patch)

### Changes

1. Workspace containment:
   - Continue validation from an APFS/local workspace, or another explicitly documented containment where macOS does not create AppleDouble sidecars inside the project or Gradle build directories.
   - Preserve the existing SCH-2 implementation diff while moving/copying/retargeting the active workspace.
   - Remove current `._*` sidecars from the active project only after the workspace strategy is approved; verify no generated artifacts enter the Git diff.
   - Do not treat one-off `dot_clean` on ExFAT as sufficient unless repeated Gradle validation proves AppleDouble files are not recreated.
2. Local Android SDK config:
   - Update ignored `local.properties` in the active workspace to use the reachable SDK path, `sdk.dir=/Users/tpov/Library/Android/sdk`, or provide an equivalent documented environment override for every Gradle run.
   - Prefer a checked preflight assertion that fails fast if `sdk.dir` points to a non-existent directory.
3. Firebase client config:
   - Provide the ignored `apps/android-next/google-services.json` for Firebase project `school-quiz-89336951` and Android package `com.tpov.schoolquiz.next`.
   - Verify only file presence/package/project metadata needed for Gradle; do not print file contents and do not commit the file.
   - If the source or package/project match is ambiguous, pause and involve the user; add firebase/security review only if someone proposes committing the file or changing Firebase config handling.
4. Build-environment regression guard:
   - Add or document a preflight guard for future implementation runs that fails before dev fan-out when any of these are true: active workspace contains `._*` sidecars, `local.properties` points to a missing SDK, or `apps/android-next/google-services.json` is absent for app-level gates.
   - The guard should be safe to run without printing secrets.
5. Staged validation after recovery:
   - Confirm `find . -path './.git' -prune -o -name '._*' -print -quit` produces no output in the active project.
   - Run `./gradlew :buildSrc:compileKotlin --no-configuration-cache`.
   - Run `./gradlew :apps:android-next:assembleDebug --no-configuration-cache`.
   - Run the relevant SCH-2 checks, including instrumented test APK compilation if `AppShellScreenTest` remains changed.
   - Run `./gradlew ciCheck --no-configuration-cache`.
   - Return to phase-01 implementation/review flow so the review owner can launch mandatory reviewers after build `PASSED`.

### New / Updated Tests

- `build_environment_preflight_rejects_appledouble_sidecars`: GIVEN the active project contains AppleDouble `._*` files outside `.git` WHEN the preflight guard runs THEN it fails before Gradle/dev fan-out and reports the first offending path without deleting anything.
- `build_environment_preflight_validates_local_sdk_dir`: GIVEN `local.properties` has `sdk.dir` pointing to a missing directory WHEN the preflight guard runs THEN it fails with the configured path and the expected remediation.
- `build_environment_preflight_requires_android_next_google_services`: GIVEN `apps/android-next/google-services.json` is absent WHEN app-level Gradle gates are required THEN the preflight guard fails without printing any secrets or suggesting committing the file.
- `sch2_phase01_gradle_gate_after_recovery`: GIVEN the recovered environment WHEN the staged Gradle commands run in order THEN `:buildSrc:compileKotlin`, `:apps:android-next:assembleDebug`, relevant SCH-2 tests, and `ciCheck` pass.

### Regression risk

- Medium.
- Related areas to verify:
  - Active workspace location and preservation of uncommitted SCH-2 changes.
  - Ignored local config remains untracked and secrets are not printed or committed.
  - Gradle build cache/build directories do not retain AppleDouble or stale generated artifacts.
  - Existing SCH-2 UI/test diff is still the only product diff after environment recovery.

### Rollback plan

If recovery introduces unrelated local breakage, stop Gradle daemons, return to the previous workspace copy, and keep the existing SCH-2 source diff untouched. Revert only local environment/provisioning changes made during recovery (`local.properties`, copied/moved workspace, generated build outputs, and ignored Google Services file placement). Do not discard user or feature source changes without explicit user approval.

## Apply Method

Recommendation: Via полный pipeline pass.

### Direct apply (если scope = small)

Not recommended and not eligible for this Fix Spec as written: the fix is not a 1-5 line source-code change, requires user-local provisioning, and depends on a correct ignored `google-services.json` plus a durable workspace strategy.

### Via полный pipeline pass (если scope = medium/large)

Recommended. Treat this Fix Spec as the input to a new plan/implementation pass focused on environment recovery and preflight validation, then resume the SCH-2 implementation gate and mandatory reviewers from a clean build environment.

### Deferred (если severity = low или риск высокий)

Allowed only if the user explicitly wants to pause SCH-2. Because severity is `blocker`, deferring means the current phase remains unable to complete Gradle validation/review.
