## Audit note
[03-decisions.md](/home/Programming/Android/schoolquiz4.0/docs/features/home-and-my-quests/03-decisions.md:516) contains ADR-HMQ-01..06 and ADR-HMQ-09 only. ADR-HMQ-07/08 have no superseded/deleted note, which weakens traceability before we even get to the content.

## High-Level ADRs

### ADR-HMQ-01
**Severity:** MEDIUM. **Evidence:** ADR says subcollections make the cross-catalog query “невозможно одним Firestore query” ([ADR](/home/Programming/Android/schoolquiz4.0/docs/features/home-and-my-quests/03-decisions.md:524)), but the hard requirement in the spec is only the quest-level cross-catalog filter ([spec](/home/Programming/Android/schoolquiz4.0/docs/features/home-and-my-quests/0-spec.md:444)), and Firestore collection-group queries were not considered ([Firebase docs](https://firebase.google.com/docs/firestore/security/rules-query)). **Attack:** The rationale over-claims impossibility and jumps from “quests need cross-catalog lookup” to “all 6 levels must be flat.” **Suggested addition:** State why descendants also must be top-level, or admit flat-all-levels is a chosen backend tradeoff, not a forced constraint.

### ADR-HMQ-02
**Severity:** HIGH. **Evidence:** ADR frames Query B’s downside as only “потенциально лишние docs” and “два round-trips” ([ADR](/home/Programming/Android/schoolquiz4.0/docs/features/home-and-my-quests/03-decisions.md:539), [ADR](/home/Programming/Android/schoolquiz4.0/docs/features/home-and-my-quests/03-decisions.md:552)), while prior-art says `contentsVersion` early-exit is critical for cost control ([prior-art](/home/Programming/Android/schoolquiz4.0/docs/features/home-and-my-quests/05-prior-art.md:90)) and the spec explicitly accepts cursor reset to `0` after process death ([spec](/home/Programming/Android/schoolquiz4.0/docs/features/home-and-my-quests/0-spec.md:1168)). **Attack:** On cold start and after process death, Query B without `catalogId` becomes a global public-quest scan. That is not “some extra docs”; it is the expensive path. **Suggested addition:** Add an explicit caveat for bootstrap/recovery read amplification and require metrics or a bounded fallback.

### ADR-HMQ-03
**Severity:** HIGH. **Evidence:** ADR treats `lastModifiedAt > cursor` as a clean “единый скалярный cursor” ([ADR](/home/Programming/Android/schoolquiz4.0/docs/features/home-and-my-quests/03-decisions.md:575)), but the spec stores cursor as `Long` millis and advances to `max(lastModifiedAt)` ([spec](/home/Programming/Android/schoolquiz4.0/docs/features/home-and-my-quests/0-spec.md:86)); the same spec also requires server fan-out updates across many descendants ([spec](/home/Programming/Android/schoolquiz4.0/docs/features/home-and-my-quests/0-spec.md:94)). **Attack:** Long-millis plus strict `>` has an obvious tie-loss failure mode, and invariant B is exactly the workload most likely to create timestamp collisions. **Suggested addition:** Record that millis precision is lossy unless paired with a tie-breaker or replay window.

### ADR-HMQ-04
**Severity:** BLOCKER. **Evidence:** ADR calls invariant A/B a “hard backend dependency” yet says phase-01 “работает в degraded mode” and “не блокирует client phase-01” ([ADR](/home/Programming/Android/schoolquiz4.0/docs/features/home-and-my-quests/03-decisions.md:585), [spec](/home/Programming/Android/schoolquiz4.0/docs/features/home-and-my-quests/0-spec.md:458)); grounding marks the same backend work as required ([grounding](/home/Programming/Android/schoolquiz4.0/docs/features/home-and-my-quests/2-grounding.md:67), [grounding](/home/Programming/Android/schoolquiz4.0/docs/features/home-and-my-quests/2-grounding.md:500)), and AC#34/#58 only pass if invariant B exists ([spec](/home/Programming/Android/schoolquiz4.0/docs/features/home-and-my-quests/0-spec.md:1136), [spec](/home/Programming/Android/schoolquiz4.0/docs/features/home-and-my-quests/0-spec.md:1175)). **Attack:** “Degraded mode” is just “the named feature does not work yet.” Worse, the spec elsewhere still talks about manual parent propagation as an MVP mitigation ([spec](/home/Programming/Android/schoolquiz4.0/docs/features/home-and-my-quests/0-spec.md:592), [spec](/home/Programming/Android/schoolquiz4.0/docs/features/home-and-my-quests/0-spec.md:1021)), so the dependency story is internally inconsistent. **Suggested addition:** Name the backend owner, artifact, and gate; if phase-01 ships without it, explicitly rename scope to catalog-only sync.

### ADR-HMQ-05
**Severity:** MEDIUM. **Evidence:** ADR says phase-01 is “integration mode” and any business-rule change after approval is an architectural mismatch ([ADR](/home/Programming/Android/schoolquiz4.0/docs/features/home-and-my-quests/03-decisions.md:601)), but research already had to close multiple design-level mismatches after grounding, including navigation, auth, sync structure, and persistence strategy ([research](/home/Programming/Android/schoolquiz4.0/docs/features/home-and-my-quests/1-research.md:32), [research](/home/Programming/Android/schoolquiz4.0/docs/features/home-and-my-quests/1-research.md:395)). **Attack:** Protecting the skeleton is sensible; freezing it against grounded contradictions is not. This can turn “approved” into “unfixable.” **Suggested addition:** Preserve the skeleton by default, but allow narrowly-scoped domain amendments when grounding disproves the spec.

### ADR-HMQ-06
**Severity:** LOW. **Evidence:** ADR says the one-way chain is scanner-verified ([ADR](/home/Programming/Android/schoolquiz4.0/docs/features/home-and-my-quests/03-decisions.md:616)), but that verification is limited to the Walking Skeleton domain modules ([research](/home/Programming/Android/schoolquiz4.0/docs/features/home-and-my-quests/1-research.md:164)); the spec already expects cross-module integration to live in `shared/core/sync` or a dedicated integration module ([spec](/home/Programming/Android/schoolquiz4.0/docs/features/home-and-my-quests/0-spec.md:1175)). **Attack:** The rule is real, but the proof is narrower than advertised. The dangerous coupling will happen in data, DI, and integration code, not in the already-linear skeleton. **Suggested addition:** Define the allowed composition layers and forbid reverse dependencies there too.

### ADR-HMQ-09
**Severity:** MEDIUM. **Evidence:** ADR leans on “ломает все 4 fakes” and SRP ([ADR](/home/Programming/Android/schoolquiz4.0/docs/features/home-and-my-quests/03-decisions.md:632)), but the real blocker is simply that `UserStatsRepository` has no UID API and `UserStats` has no `uid` field ([grounding](/home/Programming/Android/schoolquiz4.0/docs/features/home-and-my-quests/2-grounding.md:19)); meanwhile production already has two guest semantics: `AuthRepository` returns `null`, `UserStatsRepositoryImpl` maps to `_local` ([grounding](/home/Programming/Android/schoolquiz4.0/docs/features/home-and-my-quests/2-grounding.md:27)). **Attack:** The decision may still stand, but the justification is weakly framed and the real risk is semantic drift between two identity sources. **Suggested addition:** Document the null-vs-`_local` split and ban mixing them inside sync logic.

## Component ADRs

### ADR-CMP-49
**Severity:** BLOCKER. **Evidence:** ADR says recursion is “чище и расширяемее” and depth 6 makes stack safety a non-issue ([ADR](/home/Programming/Android/schoolquiz4.0/docs/features/home-and-my-quests/03-decisions.md:28), [ADR](/home/Programming/Android/schoolquiz4.0/docs/features/home-and-my-quests/03-decisions.md:87)), yet the same file leaves auth/shelf behavior unresolved in OQ-CMP-1/2 ([ADR](/home/Programming/Android/schoolquiz4.0/docs/features/home-and-my-quests/03-decisions.md:505)), current `Syncable` still returns only `Result<Unit>` ([research](/home/Programming/Android/schoolquiz4.0/docs/features/home-and-my-quests/1-research.md:181)), and the sketch hand-waves `changedParentIds` out of that contract ([ADR](/home/Programming/Android/schoolquiz4.0/docs/features/home-and-my-quests/03-decisions.md:68)). **Attack:** Stack overflow was never the real risk. The unresolved issue is contract shape: parent IDs, cursor advancement, auth, guest mode, and retry semantics are not actually settled. **Suggested addition:** Lock the step result type and guest/auth rules before blessing recursion as “accepted.”

### ADR-CMP-51
**Severity:** HIGH. **Evidence:** ADR says Decompose is consistent with existing navigation and avoids paradigm mix ([ADR](/home/Programming/Android/schoolquiz4.0/docs/features/home-and-my-quests/03-decisions.md:168)), but prior-art’s own Decompose section highlights `instanceKeeper`/`stateKeeper` as the ViewModel analog ([prior-art](/home/Programming/Android/schoolquiz4.0/docs/features/home-and-my-quests/05-prior-art.md:198)), while the ADR sample uses only a lifecycle scope ([ADR](/home/Programming/Android/schoolquiz4.0/docs/features/home-and-my-quests/03-decisions.md:142)). **Attack:** “Follow the existing pattern” is not enough when the researched best practice is stricter than the existing pattern. It also silently expands scope by forcing `HomeQuests` debt cleanup into the same phase. **Suggested addition:** Separate “MyQuests state holder choice” from “HomeQuests refactor now,” and add an explicit config-change retention story.

### ADR-CMP-52
**Severity:** HIGH. **Evidence:** ADR’s main argument is a repository-level filter has a race and DAO filtering protects the UI ([ADR](/home/Programming/Android/schoolquiz4.0/docs/features/home-and-my-quests/03-decisions.md:204)), but the spec already requires physical delete on archived sync ([spec](/home/Programming/Android/schoolquiz4.0/docs/features/home-and-my-quests/0-spec.md:903), [spec](/home/Programming/Android/schoolquiz4.0/docs/features/home-and-my-quests/0-spec.md:1155)); the real unresolved leak is orphaned rows after parent delete ([spec](/home/Programming/Android/schoolquiz4.0/docs/features/home-and-my-quests/0-spec.md:715), [spec](/home/Programming/Android/schoolquiz4.0/docs/features/home-and-my-quests/0-spec.md:885)). **Attack:** The stated problem is partly invented. If archived rows are deleted as contracted, DAO filtering is secondary; it does nothing about orphan quest/section joins, which is what phase-01 will actually expose. **Suggested addition:** Explicitly say DAO `archived=0` does not address orphans and define the intended parent-missing behavior.

### ADR-CMP-53
**Severity:** BLOCKER. **Evidence:** ADR says destructive migration is “проще и надёжнее” and acceptable because pre-production ([ADR](/home/Programming/Android/schoolquiz4.0/docs/features/home-and-my-quests/03-decisions.md:244)), but the database is shared with `UserStatsEntity` ([AppDatabase.kt](/home/Programming/Android/schoolquiz4.0/shared/core/persistence/src/commonMain/kotlin/com/tpov/schoolquiz/shared/core/persistence/AppDatabase.kt:7)), and offline-first AC assumes cached data keeps working ([spec](/home/Programming/Android/schoolquiz4.0/docs/features/home-and-my-quests/0-spec.md:1133)). **Attack:** This is not just catalog cache loss. It can wipe unrelated shell/user state and force a guest/offline regression after update. “Pre-production” does not remove the engineering obligation to name that blast radius. **Suggested addition:** Explicitly list which existing data is lost, or constrain destructive migration so unrelated state survives.

### ADR-CMP-55
**Severity:** MEDIUM. **Evidence:** ADR says `commonTest` makes tests “переиспользуемы на обоих targets” ([ADR](/home/Programming/Android/schoolquiz4.0/docs/features/home-and-my-quests/03-decisions.md:272)), but current persistence still lacks `kspJvm` ([build.gradle.kts](/home/Programming/Android/schoolquiz4.0/shared/core/persistence/build.gradle.kts:39), [prior-art](/home/Programming/Android/schoolquiz4.0/docs/features/home-and-my-quests/05-prior-art.md:309)), and app-shell data already uses `jvmTest` in practice ([UserStatsRepositoryImplTest.kt](/home/Programming/Android/schoolquiz4.0/shared/feature/app-shell/data/src/jvmTest/kotlin/com/tpov/schoolquiz/shared/feature/app_shell/data/UserStatsRepositoryImplTest.kt:1)). **Attack:** Source-set choice is being sold as execution coverage. That is not the same thing. **Suggested addition:** Define which suites belong in `commonTest`, which in `jvmTest`, and which CI tasks are the real gate.

### ADR-CMP-50
**Severity:** MEDIUM. **Evidence:** ADR says `Quest.version` is “достаточно для correctness” and appends `?v=` after URL resolution ([ADR](/home/Programming/Android/schoolquiz4.0/docs/features/home-and-my-quests/03-decisions.md:300)), while the resolver already returns a full Firebase Storage download URL ([FirebaseCatalogModule.kt](/home/Programming/Android/schoolquiz4.0/platform/firebase/src/main/kotlin/com/tpov/schoolquiz/platform/firebase/di/FirebaseCatalogModule.kt:16)) and the spec expects version bumps for non-image writes too ([spec](/home/Programming/Android/schoolquiz4.0/docs/features/home-and-my-quests/0-spec.md:592)). **Attack:** The ADR assumes URL concatenation is trivial and over-invalidation is harmless. Neither is verified. This can refetch images on unrelated entity changes and may be brittle if the resolved URL already has query parameters. **Suggested addition:** State the accepted over-fetch cost and require safe query-parameter appending rather than raw string concatenation.

### ADR-CMP-TC
**Severity:** HIGH. **Evidence:** ADR focuses on placement and `@ProvidedTypeConverter` ([ADR](/home/Programming/Android/schoolquiz4.0/docs/features/home-and-my-quests/03-decisions.md:341), [ADR](/home/Programming/Android/schoolquiz4.0/docs/features/home-and-my-quests/03-decisions.md:355)), but the current build still has only `kspAndroid` ([build.gradle.kts](/home/Programming/Android/schoolquiz4.0/shared/core/persistence/build.gradle.kts:39)) and the live builder does not add any converter instance ([PersistenceModule.kt](/home/Programming/Android/schoolquiz4.0/shared/core/persistence/src/androidMain/kotlin/com/tpov/schoolquiz/shared/core/persistence/di/PersistenceModule.kt:11)). **Attack:** Placement is not the blocker. Tooling and builder wiring are. The ADR solves the shelf label while the floor is missing. **Suggested addition:** Make `kspJvm` and `.addTypeConverter(StringSetConverter())` explicit prerequisites, not implied follow-ups.

### ADR-CMP-FAKE
**Severity:** HIGH. **Evidence:** ADR says the project needs one standard fake blueprint ([ADR](/home/Programming/Android/schoolquiz4.0/docs/features/home-and-my-quests/03-decisions.md:375)), but current fakes already encode richer, repo-specific behavior: `FakeQuestRepository` simulates Query A+B, delete-markers, and cursor advance ([FakeQuestRepository.kt](/home/Programming/Android/schoolquiz4.0/shared/feature/quest/domain/src/commonTest/kotlin/com/tpov/schoolquiz/shared/feature/quest/domain/fake/FakeQuestRepository.kt:27)); section/theme fakes model cursor filtering and archived deletes differently ([FakeSectionRepository.kt](/home/Programming/Android/schoolquiz4.0/shared/feature/section/domain/src/commonTest/kotlin/com/tpov/schoolquiz/shared/feature/section/domain/fake/FakeSectionRepository.kt:15)). **Attack:** This is standardization for its own sake. A lowest-common-denominator fake API will flatten exactly the semantics phase-01 tests need to catch. **Suggested addition:** Define a minimum shared contract, but allow repo-specific helpers where production behavior differs.

### ADR-CMP-NAV-45
**Severity:** MEDIUM. **Evidence:** ADR says `OpenQuestCreate` needs dedicated push semantics and cross-tab behavior ([ADR](/home/Programming/Android/schoolquiz4.0/docs/features/home-and-my-quests/03-decisions.md:467)), but the actual UI trigger is the FAB on `MyQuests` only ([grounding](/home/Programming/Android/schoolquiz4.0/docs/features/home-and-my-quests/2-grounding.md:212)); even the ADR sample is not compile-correct (`activeTab = DrawerSection.LocalSection`) ([ADR](/home/Programming/Android/schoolquiz4.0/docs/features/home-and-my-quests/03-decisions.md:477)). **Attack:** The compile error was real; the accepted semantics partly solve invented edge cases. That increases state-machine surface without a user-driven need. **Suggested addition:** Mark cross-tab `OpenQuestCreate` as future/programmatic behavior, not a guaranteed UI path, and keep the example code exact.
