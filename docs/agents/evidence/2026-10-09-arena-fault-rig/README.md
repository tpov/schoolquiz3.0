# 3.3 server half — arena fault/fixture rig (story 3.3, epic-arena-completion) — 2026-10-09

Смешанная история: серверная половина (манифест демо-фикстур + прокси submit-mutation-drop,
привязанный к demo-backend) диспетчируема с этого дерева; device-половина (real-offline,
подготовленный тикет) остаётся hitl. Здесь зафиксированы обе серверные половины; история
остаётся открытой до device-половины.

## Часть A: демо-фикстуры ролей/банков (`scripts/demo-fixtures/`, коммит afc1a486→9e06a8b1)

Манифест `manifest.json` (schemaVersion 2) + идемпотентный seeder + read-only верификатор.

- **Роли:** закреплённые экспорт-era авторы ac-цепочек (`D0h0rHZG…` — банк-low,
  `1qWvMnl9…` — банк-high; auth-аккаунты существуют с восстановления 04.10, только
  сверяются); засеянные `demoarena_curator_m` (профиль adminLevel 100 — isArenaCurator),
  `demoarena_player_a/b` (профили + users с gold 100000; профили нужны, потому что
  submitMutation требует доверенный профиль вызывателя — requireProfile).
- **Банки:** `ac_0ecb34…_lesson_1` — цена **1** (закреплённый экспорт-era рейтинг 2★,
  42/21 — низ юниверса), `ac_6ba84b00…_lesson_1` — цена **100** (засеянный рейтинг 3★,
  43/21 — верх). Цены относительные (assignLessonPrices): минимум шкалы → 1, максимум →
  100; проверено живым юниверсом.
- **Ноль перезаписей:** seeded-доки создаются/сверяются, закреплённые предпосылки
  (уроки/квесты/каталоги/рейтинг bank-low) только сверяются; расхождение — именованный
  отказ. Честный inventory демо-бэкенда: REST-чтение закрытых правилами коллекций
  выглядит как «пусто» (403) — инвентаризация только через admin-SDK.
- **Базовая линия юниверса:** 15 строк экспорт-era фикстур (четыре ac-цепочки, aeu_*,
  один lesson-UUID банк); верификатор держит банки на экстремумах (1 и 100) при любом
  составе — будущая фикстура, сдвинувшая экстремум, роняет проверку, а не молчит.
- **Проверка:** `fixtures-verification.log` — продакшн-`createArenaEligibleUniverse` с
  продакшн-лоадером контекста (захват при загрузке index.js, как в
  arena-eligible-universe-emulator-test) против демо-бэкенда: VERIFIED, цены 1 и 100.
  `fixtures-seeding-idempotent.log` — повторный прогон: created 0, verified 24.
- Сезонные фикстуры (3.12: четверти, 19/20 различных прошлых) — отложены в 3.12, здесь
  не засеиваются (manifest.json → seasonFixtures).

## Часть B: прокси, привязанный к demo-backend (`submit-drop-server-fault-run.js`)

Скриптованный клиент вместо приложения — матричная строка «потеря ответа после server
commit, повтор прежнего ID» на серверной половине; outbox/Maestro-прогон остаётся
device-половиной.

- **Подъём:** хостовый functions-эмулятор (`firebase emulators:start --only functions`,
  порт 5001, npx firebase-tools 15.x как в drain 2.7) с ambient-окружением
  `FIRESTORE_EMULATOR_HOST=127.0.0.1:18090`, `FIREBASE_AUTH_EMULATOR_HOST=…:19090` —
  функции пишут в живой demo-backend. После прогонов остановлен (порты 5001/8042
  освобождены), демо-контейнер не тронут.
- **Тело мутации:** `lesson_runner.SUBMIT_ATTEMPT` на home-уроке демо `mvp-smoke-v2`
  (валидированная тест-фикстура бэкенда, тот же урок, что играл офлайн в hitl 2.7);
  capturedTerms = полная payable-проекция живой `configs/economy` (mutation-terms.js),
  attemptId 64-hex, payload — строка (контракт прокси `isExactTarget`). Арена-вариант
  строки требует подготовленного тикета (`ARENA_TICKET_REQUIRED` воспроизведён честным
  отказом) — это device-половина 3.4; транспорт и ключ идемпотентности от урока не
  зависят.
- **Прогон** (`server-fault-run.log`, приватные артефакты в 0700-каталоге, аудит —
  `proxy-audit.json`, только хеши):
  1. запрос через прокси — upstream ответил 200 (569 байт), соединение с клиентом
     оборвано; аудит: `EXACT_TARGET_SENT_UPSTREAM → EXACT_TARGET_UPSTREAM_HEADERS(200) →
     UPSTREAM_RESPONSE_COMPLETE_AFTER_DROP`;
  2. сервер: `mutation_keys` завершён (state=completed, termsVersion=0 = версии таблицы),
     ровно одна квитанция — эффект есть, хотя ответ потерян;
  3. точный повтор через прокси — локальный обрыв (`EXACT_TARGET_BLOCKED_AFTER_DROP`),
     upstream не контактирует;
  4. повтор мимо прокси, прямо upstream — `{replayed: true}`, результат идентичен,
     `completedAtMs` не изменился, квитанция по-прежнему одна, состояние игрока не
     тронуто — **второго финансового эффекта нет**;
  5. итог аудита: `UPSTREAM_CONFIRMED_AND_DOWNSTREAM_DROPPED` (после STOPPED — без
     изменения вердикта), все ожидаемые события на месте.
- **Гигиена демо:** два завершённых ключа фикс-игрока (два полных прогона, включая
  отладочный — оба осели штатно), зависших резерваций нет; списание жизненных очков —
  штатный эффект попыток; probe-отказы (`ARENA_TICKET_REQUIRED`) прошли до резервации
  ключа и следов не оставили.
