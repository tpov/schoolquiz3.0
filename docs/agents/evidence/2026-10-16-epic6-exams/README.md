## Что построено

Сервер (`functions/`, CommonJS, тесты — assert-скрипты через `run-tests.js`):

- `exam-bank.js` — одобренный пул темы/курса: каноническое схлопывание переводов, один источник
  стоимости на канонический вопрос (детерминированный минимальный документ, замораживаемый
  манифестом сидинга), границы набора 5/15/20, сертификационные своды курса (пересчитываются,
  не инкрементируются), Survey исключён.
- `exam-coverage.js` — C3: требуемые EASY-манифесты урока, союз полнозачётных токенов по
  засчитанным попыткам, неизвестное наследие — ожидание, барьер материализации.
- `exam-admission.js` — чистый оценщик допуска: восстановление открытого сидинга первым,
  явная недоступность, условия, банк, прогресс (Locked / ResultsNotSynced), кулдауны 24ч/168ч с
  включённой гранью, плата только СТАНДАРТНЫМИ очками.
- `exam-sitting.js` — шесть вызовов: старт с атомическим списанием 100/200, восстановление без
  второго списания, первый ограниченный ACK, первый-ответ-побеждает с прочной квитанцией, запрос
  закрытия, явное открытое состояние или терминальный результат. Плюс отдельные документы
  свидетельства сидинга (канонические содержимые, ключи, выданные перестановки — только сервер).
- `exam-scoring.js` — all-HARD ответное время (100 символов → 24с, пол 5с; 0.75 не существует),
  общий скорер по слотам (неотвеченное = 1), вложенное усечение процента, линейные звёзды темы
  `floor((30p+50)/100)`, безопасный совет фиксированной длины.
- `exam-reward.js` — C1: полосы обычного тарифа, режимные коэффициенты (тема ×3 только первый
  проход; финал ×10 нового / ×0.1 повторного против durable максимума `b`), независимое
  half-up округление XP и ноликов от одного нераскруглённого N, ноль всё равно двигает `b`,
  проверка замороженной основы до калькулятора (TE>=25/TH>=75 тема; TE=0/TH>=100 финал).
- `exam-terminal.js` — единственный терминальный писатель: аренда+nonce, ограниченные шаги,
  изоляция яда, цепочка таймаутов с якорем окна к ИСХОДНОМУ дедлайну, один коммит
  (результат + кулдаун + деньги + [финал: факт выпуска + работа подписывания]), испорченная
  база — яд, а не фальшивая выплата. `exports.reconcileExamSittings` в `index.js` — экспорт
  onSchedule, НИЧЕГО не развёрнуто и не включено.
- `exam-certificates.js` — неизменяемые факты выпуска (год действия, даты свои), явное ожидание
  подписи, подпись ВНЕ транзакции с fence/CAS по (issuanceId, claimsDigest, fence), публикация
  только подписанного снимка, политика верификации по собственным датам/ключам, профиль —
  последний заработанный по порядку заработка. Подписант — подключаемый шов Q-EX-5; в
  `index.js` связка `signer: null` — ключей нет, выпуски остаются в явном ожидании.
- `exam-corrections.js` — C2: подотчётные исключения с CAS головы, переигрывание по
  correctionId, пересчёт из исходных слотов внутри транзакции, барьер поколения темы
  (`exam_theme_generation`), UNSCORABLE_ALL_EXCLUDED / CORRECTION_PENDING_EVIDENCE без чисел.
- `exam-contract-fixtures.test.js` — EXAM-TECH-1 исполняется: weightedTariff (8), rewardCases
  (13), worthCases (2), correctionCases (7), arithmeticOnlyCases (1, синтетический шов с
  явной пометкой), invalidBasisCases (2, отказ без выплаты).
- `exam-round-trip.test.js` — приёмочные случаи 1–3, 8, 11, 14 на фейковом эмуляторе:
  фикс-банк курса/темы → покрытие → старт темы (списание 100) → ACK/ответ/восстановление →
  терминальный результат (звёзды/проход/кулдаун/награда первого прохода) → 12 тем → финал
  (200; плазменный богач без стандартных очков — отказ) → факт выпуска + ожидание подписи →
  верификация вне входа; грани кулдауна 24ч/168ч; A→B→A.

Shared Kotlin:

- `shared/feature/lesson-runner/domain/.../model/ExamSittingModels.kt` — проекции сидинга,
  типизированные отказы, квитанции, результат с серверными значениями.
- `.../logic/ExamRunRules.kt` — зеркала отображения: all-HARD таймер (100→24с, 10→5с, никакой
  сложности-зависимости), линейные звёзды, вердикт ACK'а (первый закрепляет, дубликат
  возвращает, опоздавший не удлиняет), разбор ТОЛЬКО редактированной иерархии.
- `shared/core/scoring/.../ExamAssessmentArithmetic.kt` — C1/C2 арифметика Kotlin-стороны;
  `ExamContractFixturesParityTest` гоняет копию `assessment-contract-fixtures.json`
  (`shared/core/scoring/src/jvmTest/resources/`) по тем же случаям, что и JS.
- `shared/feature/lesson-runner/data/.../remote/ExamSittingWireParser.kt` +
  `ExamSittingRemoteDataSource.kt` + `ExamCertificateRemoteDataSource.kt`; строгие формы с
  опциональными ключами по контракту; приватный ключ в публичном ответе = испорченная форма.
- `platform/firebase/.../exam/FirebaseExamSittingRemoteDataSource.kt` (+ сертификаты) — шесть
  вызовов с сессионным забором (A→B→A), DI в `FirebaseModule.kt`.

Android:

- `android/feature/lesson-runner/presentation/.../exam/` — витрина допуска (типизированные
  отказы, согласие на условия, кулдаун с доступностью), сидинг (ACK → ответ → следующий,
  восстановление тем же намерением), ожидание закрытия, результат без пересчёта и без
  правильностных пометок на квитанциях. Логика — JVM-проверяемая `ExamRunStateMachine`.
- `android/feature/exam/presentation/` (новый модуль, зарегистрирован в settings) — список
  сертификатов (последний заработанный по порядку заработка, ожидание подписи явно) и вход
  публичной верификации вне входа.

## Что остаётся за владельцем (Q-EX-5 и деплой)

- Активация и деплой: `reconcileExamSittings` — только экспорт; расписание, окружение,
  maxInstances — решение владельца. Ничего не развёрнуто.
- Подписывание: провайдер/алгоритм/секреты/бюджеты — Q-EX-5. Шов готов
  (`createCertificateSigning({signer})`, материалы верификации публикуются до применения,
  старые удерживаются), связанного подписанта нет — выпуски остаются в восстановимом ожидании,
  неподписанная публикация невозможна.
- Содержимое экранов: структура состояний построена, тексты — заглушки-ключи (`ExamText`,
  `CertificateText`) до отдельного подтверждения владельцем (протокол §Screen-content
  confirmation).
- Навигация: компоненты и фабрики DI готовы; связывание в навигационное дерево приложения —
  отдельная смена (вне Code Map этой спеки).
