## Серверная половина (кратко; детали в live-run.json и ATTEMPTS.md)

- **A. Цена заморожена сквозь settle (quote не переоценивается)**: prepare bank-low HARD по
  цене 1 → окно мутации рейтинга (легальный максимум шкалы {3,1}) поднимает котировку до 100
  (каталог живьём: 1 → 100) → settle COMPLETED 100% по конверту с `capturedTerms` →
  `consumedNolics = 1` (замороженная, не переоценённая), роялти-расщепление ровно одной нолики
  (ledger ROYALTY+SINK+CARRY = 1), замороженные 50 жизни; повтор тела — `replayed: true`,
  байт-в-байт тот же результат, ни одной новой записи. Рейтинг восстановлен байт-в-байт в
  finally, котировка вернулась к 1.
- **B1. Гонка, settle-первый**: поздний cancel по SETTLED — no-op, возвращающий статус
  `SETTLED` с квитанцией сеттлмента, ни копейки не отпустив (нет cancel-строк в ledger);
  повтор того же cancel-requestId — тот же результат (request-документ сохранён — намерение
  сверяемо); `fetchArenaEntryTicketStatus` concur.
- **B2/C. Гонка, cancel-первый + «позднее завершение не платит дважды»**: cancel вернул
  замороженные 1+50; ДВА разных тела позднего завершения (тот же attemptId, разные ответы)
  отказаны поимённо `TICKET_CANCELLED` — ноль event-документов, ноль роялти, ноль наград,
  ноль денег, ключ мутации освобождён оба раза (завершённых записей нет — **намерение
  остаётся припаркованным и сверяемым**, не сфабриковано в успех); статусная поверхность
  отдаёт CANCELLED с cancel-квитанцией — серверная правда, по которой клиентский retained
  SETTLE резолвится (клиентская машина `ArenaCancelledSettlementResolver` →
  `ARENA_RESOLVED_CANCELLED`, `lastFailure=TICKET_CANCELLED` permanent — покрыта
  JVM-тестами `ArenaCancelledSettlementResolverTest`).
- **B3. Истинная параллельная гонка cancel×settle**: ровно один финальный эффект — в прогоне
  выиграл settle (cancel ответил 200 no-op поверх SETTLED, ключ ровно один), кошелёк сместился
  ровно на награду сеттлмента, cancel-строк в ledger нет; обратный порядок детерминированно
  доказан B2. Победитель — тайминг; предмет доказательства — «ровно один» + поимённый исход
  проигравшего.
- **D. Неизвестный HARD-скор никогда не ноль**: D1 — завершение без единого ответа сеттлится
  ЧЕСТНЫМ нулём: код `11` (оба вопроса «показаны, без ответа»), ни одной `0`-цифры («не
  показан» невозможен для выданного), percent = `computePercentScore(code)`, цена выплачена,
  роялти ровно 1; D2 — неразрешённая попытка не получает никакого числа: ABORTED-тело отказано
  `EXPLICIT_CANCELLATION_REQUIRED`, тикет остаётся RESERVED с `terminal: null`, event-документа
  нет — неизвестность не записана нулём; единственный выход без ответа — явная отмена с
  замороженным возвратом 1+50. Дверь `UNSCORABLE_BANK` (server-fault → null/null по контракту
  attempt-scoring) недостижима клиентским вводом по построению: served/ключи заморожены в
  тикете сервером — честная граница, отказ вместо числа гарантирован fail-closed.
- **Финальная консервация**: нолики 8 → 4 (дельта ровно −4 = четыре сеттла по замороженной
  цене), ключи мутаций 22 → 26 (ровно по одному на успешный settle; отказы и replay не пишут),
  резервы/холды к базлайну, документ рейтинга байт-в-байт исходный, фикстуры VERIFIED.
