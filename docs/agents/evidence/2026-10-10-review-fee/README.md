# 4.7 paid-review-cycle-conservation — evidence (2026-10-10)

История: платный цикл проверки консервирует деньги (CAP-4, AD-10): плата тарифа при принятии
заявки, после полного цикла (PUBLISHED или обоснованное REJECTED) фонд делится между
проверяющими по уровням в десятых нолика, остаток сгорает; манифест расчёта неизменяем;
повтор и сохранённое evidence новой платной работы не создают; незавершённый цикл фонд не
делит и не сжигает (OQ-2 остаётся parked). hitl = false: сервер/node-история, устройство не
требуется — на риге не гонялась.

## Принятые правила денег (источники)

- Тарифы владельца (PRD «Оплата подачи на проверку», prd-discovery-snapshot.md): первоначальная
  полная подача — 1000 ноликов; перепроверка после исправлений — 100 ноликов × вопрос; плата не
  возвращается; вознаграждение = личный уровень / 10 за урок целиком (уровень 200 → 20);
  выплаты ≤ платы, превышение ужимается пропорционально; остаток сгорает.
- AD-10 (ARCHITECTURE-SPINE 2026-09-29) закрыл открытые вопросы: unit=(оплаченный цикл, урок,
  проверяющий), направления объединяются; Li фиксирует первый принятый завершённый результат;
  арифметика в десятых, floors + раздача остаточных десятых по убыванию остатка, ничья по
  стабильному unitId; floating-point запрещён; carry кошелька свой (отдельная доля Арены);
  инварианты 10P = Σentitlement + burn и oldCarry + Σentitlement = 10×credit + newCarry.

## Серверные решения этой смены (границы, а не выдумки)

1. **Тариф перепроверки** считается от ВСЕХ вопросов заявки: нынешняя модель ревью перепроверяет
   каждую новую заявку целиком (записи привязаны к submissionId), значит «вопросов, требующих
   повторной проверки», ровно questionCount. Настоящий частичный перечёт появится вместе с
   моделью сохранных проверок и унесёт свой диф — см. отчёт смены, на владельца.
2. **Тариф живёт в `configs/review_fee`** (initialSubmissionNolics / recheckQuestionNolics /
   revision), а не в `configs/economy`: server-only знание по прецеденту `configs/arena_review`;
   испорченный тариф отказывает громко (HttpsError failed-precondition), не сползая к умолчанию.
   Документа нет — действуют принятые 1000/100 (revision 1).
3. **Плата — одна транзакция с принятием заявки** (processArenaRequest переведён с батча на
   runTransaction): подача без денег не принимается; денег не хватает — окончательный
   REVIEW_FEE_INSUFFICIENT, ключ мутации освобождается. Идемпотентность платы — документ
   `review_fee_cycles/{submissionId}`: повтор приёмки (крэш после эффекта, догоняющий обработчик)
   плату не повторяет. Гонка «две приёмки одной заявки» закрыта транзакцией.
4. **«Первая подача» против «перепроверки»**: квест платит initial, если нет ни документа
   `review_fee_quests/{questId}` (создаётся платой), ни публичного `quests/{id}` (публикация до
   введения платы). Все последующие подачи квеста — recheck.
5. **Расчёт** (settleReviewFeeCycle) — на терминальном переходе и при каждом обращении к уже
   терминальной заявке (публикация/отклонение, повторы ревью, replay очереди): идемпотентен
   статусом SETTLED, манифест пишется tx.create (второй не существует). Кошельки, манифест и
   статус цикла — одна транзакция. Денежная цепочка durable: упавший между публикацией и
   расчётом инстанс догоняется следующим же действием на заявке.
6. **Отклонение — работа**: rejectReviewSubmission записывает `rejectedReviewerLevelAtSubmit`
   (max(tester, admin, developer) судьи) в задание; расчёт создаёт из него юнит отклонения.
   Поле добавлено в adminDocuments/adminLessonSnapshotToTask (круг документа).
7. **Граница полноты**: TESTING/LOGIC завершены оценкой урока; TRANSLATION — записью, накрывшей
   все вопросы задания содержимым (тот же предикат, что засчитывает язык); TRANSLATION_REVIEW —
   записью с явными решениями: независимо перечислить сегменты сервер не может, полнота
   принимается на интейке. Задание, переписанное новой заявкой, своё отклонение старому циклу
   не приносит (guard по submissionId).
8. **Заявки до введения платы** (циклы 4.5/4.6 на demo) цикла не имеют — расчётом не
   покрываются и манифеста не получают: распределять нечего.

## Файлы

- `functions/review-fee.js` — чистая арифметика AD-10 (тарифы, юниты, распределение, carry,
  манифест с проверкой инвариантов); BigInt-произведения, никаких float.
- `functions/review-fee.test.js` — 16 кейсов: границы ΣLi ≤/> 10P, ничьи остатков, пустой фонд,
  свип консервации (200 шагов), BigInt за пределами 2^53, фиксация уровня первым результатом,
  чужая submissionId не кормит цикл, юнит отклонения, манифест роняет битую консервацию.
- `functions/index.js` — плата в processArenaRequest (транзакция), settleReviewFeeCycle + хуки
  на PUBLISHED/REJECTED (включая терминальные ранние возвраты publishSubmissionIfReady и
  rejectReviewSubmission), `configs/review_fee`-ридер, коллекции review_fee_cycles /
  review_fee_quests / review_fee_manifests.
- `functions/currency-ledger.js` — поводы `review_fee` (−тариф у автора) и `review_reward`
  (+целые нолики у проверяющего); сгоревший остаток строкой книги не является — он факт
  манифеста (баланс никого не меняет), консервация проверяется по манифесту.
- `functions/review-fee-cycle.test.js` — приёмниковая сюита на стабе Firestore (настоящие
  submitMutation/submitReviewAction/rejectReviewSubmission): сквозная консервация, carry между

- `functions/_firestore-stub.js` — snapshot.ref дополучил set/update (путь failedStages в
  publishSubmissionIfReady раньше на стабе не гонялся); аддитивно, чужие сюиты не затронуты.
- `functions/quest-authoring-submission-invariants.test.js` — инвариант «заявка денег не читает»
  заменён контрактом платного цикла (списание ровно один раз, отказ до записей, тариф перепроверки).
- `functions/sync-change-clock.test.js` — текстовая проверка прежнего инварианта
