# Инструкция агенту, ведущему одно устройство

Ты отвечаешь **за одно устройство**. Чужие устройства не трогаешь никогда: любая команда
`adb` идёт строго с `-s <твой serial>`.

## Инструменты

```
ADB=/opt/homebrew/bin/adb                      # только этот бинарник, других не запускать
./scripts/devices/dump.sh <serial> [сек]       # дерево элементов, с жёстким таймаутом
./scripts/devices/dump.sh <serial> | python3 scripts/devices/inspect.py [фильтр]
./scripts/devices/ui.sh <serial> find  <текст>
./scripts/devices/ui.sh <serial> tap   <текст>
./scripts/devices/ui.sh <serial> fill  <подпись> <значение>
./scripts/devices/ui.sh <serial> hidekb
./scripts/devices/ui.sh <serial> text
./scripts/devices/ui.sh <serial> shot  <файл.png>
./scripts/devices/ui.sh <serial> back
```

## Запреты

1. **Никаких нажатий по координатам вслепую.** Только `ui.sh tap/fill`, которые сначала
   находят элемент в дереве. Причина: на прошлой попытке слепое нажатие попало в личный
   Telegram владельца устройства. Если элемент не находится — сообщай, а не подбирай точку.
2. **Не выходить из приложения `com.tpov.schoolquiz`.** Не открывать другие приложения, не
   лазить в системные настройки. Pixel `56271FDCH00C5S` — личный телефон владельца.
3. **Ничего не удалять и не переустанавливать**, не выдавать разрешения через настройки.
4. **Не менять `ANDROID_HOME`, не перезапускать сервер adb.** Однажды это подвесило adb
   целиком и остановило прогон.
5. **Не править код приложения и серверные файлы.** Ты испытываешь, а не исправляешь.

## Грабли, уже найденные — не наступай второй раз

- **Ввод только латиницей.** `adb shell input text` не передаёт кириллицу: символы просто
  не доходят. Пиши значения латиницей (`Progon 0309`, `Razdel`).
- **Клавиатура закрывает нижние поля.** При её появлении форма прокручивается вверх примерно
  на 140 точек, и нажатие по нижнему полю попадает в клавиатуру, а текст продолжает литься в
  прежнее поле. `ui.sh fill` это уже учитывает: закрывает клавиатуру, ждёт, берёт свежие
  координаты. Пользуйся `fill`, а не `tap`+`type`.
- **Одной секунды ожидания мало.** После показа или скрытия клавиатуры форма едет; ждать
  нужно две секунды, иначе дамп устаревает до момента нажатия.
- **Поиск по тексту различает «Квест» и «Квесты»** только точным совпадением — оно уже
  включено в `ui.sh`, но помни при разборе.
- **Элементы с пометкой `НЕ РАЗЛОЖЕН`** (нулевой размер) нажать нельзя, даже если текст есть
  в дереве. Так ведут себя пункты нижнего меню, пока открыта форма создания.
- **Ярлыков для тестов в приложении нет** — ни одного `testTag`. Веди только по видимому
  тексту и по описаниям (`content-desc`): нашлись только «Назад», «Открыть меню»,
  «К структуре», «Добавить фото», «Превью», «Предыдущий вопрос», «Следующий вопрос»,
  «Добавить вопрос».

## Что известно про экраны

- Заголовок хоста — «МОИ КВЕСТЫ»; слева кнопка с описанием «Открыть меню».
- Форма создания: «Создание квеста», действие «Сохранить», поле каталога (значение «Квесты»),
  затем поля «Квест», «Раздел», «Тема», «Урок» (подписи — заглушки внутри полей), отметка «RU»,
  ниже вкладки «Легкие вопросы» и «Сложные вопросы» (могут быть за нижним краем — прокрути).
- Редактор вопроса: тип («Один ответ» / «Несколько ответов» / «Порядок»), поле «Вопрос»,
  варианты «Вариант 1», «Вариант 2» с переключателями верного ответа, «Добавить вариант»,
  «Добавить вопрос», возврат по описанию «К структуре».

## Отчёт

Пиши в свой файл `_bmad-output/specs/spec-quest-lifecycle/run/devices/<роль>.md`. Только
свой файл — иначе агенты перепишут друг друга. В отчёте:

- что удалось пройти, со ссылками на снимки экрана;
- что **не** удалось и на каком именно шаге, с точной подписью элемента, который не нашёлся;
- расхождения между тем, что обещает playbook, и тем, что показало устройство;
- особенности прошивки (диалоги, локализация, отказы).

Факты подкрепляй снимком или выводом `inspect.py`. Не пиши «работает» без следа.
