# Epic 3 Context: Коробка за рекламу, которую нельзя подделать

<!-- Compiled from planning artifacts. Regenerate with compile-epic-context if planning docs change. -->

## Goal

Игрок без денег получает коробку за пять просмотренных реклам — так, чтобы коробку нельзя было
напечатать поддельным вызовом, чтобы темп оставался под серверным потолком (две коробки в сутки от
серии и рекламы), чтобы купленная и заработанная коробки не отличались содержимым, и чтобы реклама
никогда не прерывала урок. Эпик строит путь «показ → подтверждение сети → прогресс → коробка →
одно открытие по одной таблице дропа» и запирает рекламу в двух названных поверхностях.

## Stories

- Story 3.1: Награду подтверждает сеть, а не телефон
- Story 3.2: Пять реклам — одна коробка, потолок держит сервер
- Story 3.3: Купленная коробка и заработанная одинаковы
- Story 3.4: Реклама не входит в урок

## Requirements & Constraints

- Прогресс к коробке засчитывается только по серверному подтверждению рекламной сети (SSV-callback
  с подписью AdMob), не по событию показа на устройстве (NFR6). Ключ идемпотентности —
  идентификатор транзакции из подтверждения; повтор не начисляет второй раз (NFR2).
- Событие с устройства обновляет экран, но ничего не начисляет; пять поддельных вызовов с
  устройства не дают коробку. Клиент никогда не начисляет и не списывает (NFR1) — коробка
  двигается только серверной транзакцией.
- Пять засчитанных просмотров дают ровно одну коробку; четыре — ничего. Потолок «две коробки в
  сутки» (одна от серии, одна от рекламы) проверяется сервером в той же транзакции, что и выдача.
  Любой новый источник коробок обязан влезть в тот же потолок или заменить его часть.
- Содержимое коробки не зависит от способа получения: одна таблица дропа, второго перечня в коде
  нет (FR8-дисциплина). Повторное открытие одной коробки невозможно: открытие гасит счётчик в той
  же транзакции, повтор запроса отвечает записью-квитанцией.
- Реклама живёт ровно в двух местах — разблокировка коробки и экран предложений — и никогда не
  показывается в уроке (FR7). Сборка без идентификатора AdMob выключает рекламу и не падает.
- Украинский интерфейс обязателен; всякие пользовательские сообщения — ключами локализации.

## Technical Decisions

- **Сервер (functions/).** Коробки живут в `box-service.js` (операции OPEN/VISIT/OFFLINE_STREAK/
  PREMIUM_DAILY одной транзакцией, записи-квитанции в `box_operations`, повтор по operation id),
  серия — `gift-boxes.js`, дроп — `gift-box-rewards.js` (энтропия захватывается сервером до
  транзакции, рероллов нет). Константы экономики — `configs/economy` (`economy-constants.js`):
  размеры паков и «продаётся ли» живут только там. Денежный путь по чеку — `purchase-settlement.js`
  + `purchase-verification.js` (порядок Play→начисление→ответ→гашение нерушим); книга движений —
  `currency-ledger.js` (CURRENCY.BOXES уже есть). Новые деньги — по этому же образцу: чистый модуль
  решения + путь с внедрённым `db`, тестируется подделкой Firestore без firebase-admin.
- **SSV-подтверждение AdMob.** Callback приходит HTTPS-запросом от серверов Google с параметрами
  (user_id, custom_data, transaction_id, reward_amount, reward_item, timestamp, key_id, signature);
  подпись — ECDSA P-256/SHA-256, публичные ключи Google — с gstatic по key_id. Проверка подписи и
  решение — чистый модуль; endpoint — тонкая обвязка. Прогресс и потолок — на документе игрока,
  движение коробки — в существующей транзакции коробочных операций.
- **Клиент (KMP).** Рекламы в дереве ещё нет: только `AnalyticsEvent.RewardedAdCompleted` в
  `shared/core/analytics`. Домен/дата — `shared/feature/economy`; презентация —
  `android/feature/economy/presentation` и `android/feature/quest/presentation` (коробка на главном
  экране). Урок (`android/feature/lesson-runner`, `shared/feature/lesson-runner`) рекламных типов не
  импортирует — это свойство запирается тестом. State holder'ы — Decompose-компоненты; экраны
  рендерят состояние и эмитят колбэки, Koin и репозитории в экранах запрещены.
- **Конвенции.** Комментарии в `functions/` — русские, в Kotlin — по окружению; время — серверные
  часы, инжектируемые; системные часы в чистых модулях запрещены. Гейты: `node functions/run-tests.js`
  (все сьюты), `sgw ./gradlew` для Kotlin-поверхностей; сборка приложения — только assembleMvp.

## Cross-Story Dependencies

- **3.1 → 3.2.** Прогресс пяти просмотров появляется только из SSV-подтверждений; счётчик 3.2 не
  знает другого источника.
- **3.2 → 3.4.** Клиентская поверхность коробки показывает прогресс и «смотреть рекламу», опираясь
  на серверную правду 3.1–3.2; без подтверждения сети экран ничего не обещает.
- **3.3 стоит на OPEN.** Купленная коробка (грант по SKU из таблицы) и заработанная стекаются в
  один `boxCount`, содержимое решает единственный `generateGiftBoxReward` внутри OPEN.
- **Эпик 1.** Правила денег (проверка у Play, одна транзакция, квитанция, аудит, книга) —
  переиспользуются как есть; новых денежных порядков эпик 3 не вводит.
- **Среда.** Аккаунт AdMob закрыт с 01.09: живой показ, настройка консоли и настоящий callback
  невозможны — серверная половина закрепляется фикстурами (подписанные тестовые ключи), живая
  настройка — defer владельца.
