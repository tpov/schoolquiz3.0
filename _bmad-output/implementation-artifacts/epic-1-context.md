## Goal

Дать приложению один доменный тип неудачи обращения к серверу и детектор связи, чтобы решение «повторять, отложить, увести в карантин или спросить игрока» принималось по типу ошибки, а не по строке сообщения. Сегодня отсутствие сети и «не хватает золота» доходят до UI одинаково — как `error.message`; детектора связи в проекте нет вообще; `FirebaseFunctions` создаётся без `setTimeout`, поэтому спиннер живёт семьдесят секунд. Эпик ничего не ломает, серверных изменений не требует и выкатывается в одиночку, но без него не строится ни один следующий эпик: движок очереди (эпик 2) принимает решение о повторе именно по этому типу.

## Stories

- Story 1.1: Доменный тип ошибки обращения к серверу
- Story 1.2: Детектор связи
- Story 1.3: Исключение Firebase читается один раз, на границе, и с таймаутом
- Story 1.4: Синхронное действие не уходит в сеть, когда сети нет
- Story 1.5: Экран показывает ветвь, а не строку

## Requirements & Constraints

- **FR27** — ошибка транспорта мапится в доменный тип из пяти ветвей; решение о повторе принимается по типу, а не по тексту сообщения.
- **FR28** — синхронная мутация при отсутствии сети не показывает спиннер.
- **NFR2** — модуль не зависит ни от одной feature-модели и ни от `shared/core/sync`.
- **NFR5** — одна production-привязка Koin на тип; общая инфраструктура регистрируется в composition root, обработчики фич — в модулях своих фич.
- **NFR13** — гейт `./gradlew ciCheck --no-configuration-cache`; фейки вместо моков, без Turbine; Decompose `Component` вместо `ViewModel`; Compose не резолвит Koin.

Решённый параметр: **таймаут callable — 20 секунд** (было 70 по умолчанию SDK).

## Technical Decisions

- **AD-15** задаёт ровно пять ветвей ошибки: `НетСети` / `ПредусловиеНеВыполнено` / `Отказ(причина)` / `КонфликтВерсии` / `Неизвестно`. Повтор назначается для `НетСети`, `ПредусловиеНеВыполнено` и `Неизвестно`; `Отказ` переводит запись в карантин без повторов; `КонфликтВерсии` обрабатывается отдельно и в карантин не уходит.
- **AD-22** — карантин терминален; движок очереди (эпик 2) исполняет решение, которое этот тип объявляет. Значит набор решений закрыт и известен заранее: `RETRY`, `QUARANTINE`, `CONFLICT`.
- **AD-10** — общая инфраструктура регистрируется в composition root `apps/android-next/**/di/`, а не в модуле фичи.
- Слои проекта: `domain` — чистый Kotlin, `data` — Room и Firebase-адаптеры, `presentation` — Decompose, `ui` — Compose, `core` — общие контракты, `platform` — адаптеры SDK. Новый модуль `shared/core/network` относится к `core`.
- Границы проекта возвращают `Result<T>`, а `Result.failure` принимает только `Throwable` — значит доменная ошибка обязана уметь ездить через эту границу, сама `Throwable` не наследуя.
- Ветви `ПредусловиеНеВыполнено` и `КонфликтВерсии` в этом эпике только объявляются. Серверная пометка, из-за которой первая начнёт приходить, рождается в эпике 3; разбор второй — эпик 8.

## Cross-Story Dependencies

- 1.1 — фундамент: 1.3, 1.4 и 1.5 говорят на объявленном ею типе.
- 1.2 даёт `NetworkMonitor`, которым пользуется 1.4; в этом эпике у `observeOnline()` потребителя нет — прогон очереди подписывается на него в истории 2.2 следующего эпика.
- 1.3 применяет таймаут ко всем `getHttpsCallable` и отображает `FirebaseFunctionsException` в тип из 1.1.
- Наружу: движок очереди эпика 2 читает решение по каждой ветви; экран состояния эпика 4 показывает последнюю ошибку в терминах этого типа.
