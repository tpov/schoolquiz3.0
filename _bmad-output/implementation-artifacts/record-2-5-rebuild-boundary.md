# Запись: граница пересоздания базы (история 2.5)

Пересоздание схемы — разовое разрушение. Всё, у чего нет копии на сервере, исчезает вместе со
старой базой. Эта запись существует, чтобы решение принималось по проверенным числам, а не по
памяти о том, что «очереди вроде были пусты».

Механическая часть проверки: `RebuildBoundaryCheck` в debug-сорссете
(`apps/android-next/src/debug/`), печатает четыре числа и вердикт в logcat под тегом
`RebuildBoundary`. Это именно отдельный сорссет, а не флаг в рантайме: «не входит в релиз» —
свойство того, что скомпилировано, а не того, что не выполнилось. Точка входа — `DebugApplication`,
подменяющая `AppApplication` только в debug-манифесте; провайдер тут не годится, он стартует раньше
Koin, и графа зависимостей ещё нет.

Считаются **неотправленные** строки, а не все. Две очереди из трёх никогда не чистятся: доставленная
строка остаётся на месте с проставленным `sent_at_ms`. Если считать всё подряд, число равно всей
истории устройства и до нуля не доходит никогда, а вердикт `BLOCKED` перестаёт что-либо значить.
`sent_at_ms` проставляется только после того, как сервер принял пачку, поэтому «ещё null» — это
ровно «у сервера этого нет».

Снять вывод:

```bash
adb logcat -s RebuildBoundary
```

По AD-16 живых установок нет, есть только устройства разработчика и тестовые аккаунты. Это

## 2. Что теряется

Каждая из 23 сущностей текущего `AppDatabase` (версия 3) отнесена ровно к одной из двух групп.

### Есть серверный двойник — перечитается (16)

| Таблица | Почему переживёт пересоздание |
|---|---|
| `user_stats` | Счётчики игрока живут в документе пользователя на сервере |
| `catalogs` | Публичный контент, тянется заново |
| `quests` | Публичный контент, тянется заново |
| `sections` | Публичный контент, тянется заново |
| `themes` | Публичный контент, тянется заново |
| `lessons` | Публичный контент, тянется заново |
| `questions` | Публичный контент, тянется заново |
| `lesson_attempts` | Попытки уходят на сервер событиями результата; сервер их держит |
| `lesson_rating_submitted_local` | Локальная отметка «уже оценил»; сама оценка лежит на сервере |
| `lesson_result_attempt_outbox` | Очередь. Граница требует, чтобы не осталось неотправленных строк; доставленные уже лежат на сервере |
| `quest_rating_outbox` | Очередь, то же условие |
| `quest_arena_submission_outbox` | Очередь; доставленная заявка удаляется, поэтому любая строка здесь — ещё не ушедшая |
| `sync_state` | Только курсоры синхронизации; восстанавливаются полным ресинком |
| `review_assignments` | Задачи ревью раздаёт сервер, перечитываются |
| `review_assignment_questions` | То же, вместе с заданием |
| `user_profiles` | Профили лежат в серверной коллекции |

### Двойника нет — потеря принята (7)

| Таблица | Что именно теряется |
|---|---|
| `question_repetition` | Расписание повторов: когда игроку показать вопрос снова |
| `question_answers` | История ответов на отдельные вопросы |
| `quest_drafts` | Неопубликованные черновики квестов |
| `draft_sections` | Дерево неопубликованного черновика |
| `draft_themes` | Дерево неопубликованного черновика |
| `draft_lessons` | Дерево неопубликованного черновика |
| `draft_questions` | Дерево неопубликованного черновика |

Других записей во второй группе нет (NFR11). Черновики попадают сюда только в состоянии, которое
проверка считает недоехавшим: `DRAFT`, `SAVED`, `SYNC_PENDING`, `CONFLICT`, `REVIEW_QUEUED`.
Доехавшие — `SYNCED`, `REVIEW_SENT`, `PUBLISHED` — перечитаются с сервера. Набор объявлен один раз,
константой `QUEST_DRAFT_STATUSES_REACHED_SERVER`.

## Замечено попутно

`lesson_result_attempt_outbox` и `quest_rating_outbox` не удаляют доставленные строки никогда —
таблицы растут вместе с историей игрока. На границу пересоздания это не влияет (проверка считает
только неотправленные), но как отдельная гигиена это стоит завести в отложенные работы.

## Расхождение в имени, замеченное при реализации

Эпик называет таблицу расписания повторов `question_repetitions`, в коде она
`question_repetition` (`QuestionRepetitionEntity.kt:21`). Здесь использовано имя из кода. Расхождение
только в тексте эпика; на проверку и на состав групп оно не влияет.
