# School Quiz — пакет ТЗ для продолжения другим агентом

Срез состояния: 7 сентября 2026. **MVP не готов.** Этот пакет передаёт работу, а не объявляет её завершённой. При подготовке пакета код, серверные данные и установленные приложения не изменялись.

## Как передать работу

1. Дайте агенту этот каталог целиком и доступ к существующей изолированной рабочей копии. Архив документов сам по себе не содержит репозитория, SSH-ключа, серверных зависимостей или данных эмулятора.
2. Первое поручение — только [ТЗ-00](00-BASELINE-AND-CATALOG.md). Не поручайте сразу «доделать весь MVP» и не начинайте с повторного merge.
3. Следующий агент получает общий договор, актуальное состояние и **одно** следующее ТЗ. Сложные ТЗ разделены на этапы с отдельными точками проверки.
4. После каждого ТЗ требуйте отчёт: изменённые файлы, коммит, запущенные проверки, их ограничения и что осталось. Слово «реализовано» без доказательств не является приёмкой.
5. Если агент работает в другом окружении и не видит указанные пути, сначала отдельно организуйте доступ к исходникам. Не отправляйте ему резервную копию телефона, токены или production-ключи.

Чтобы экономить контекст, агенту не нужно заранее читать все будущие ТЗ и весь исторический журнал. Вначале — общий договор, продуктовые правила и назначенное ТЗ; затем только относящиеся к нему исходники. Большой JSON-реестр лучше проверять программно и выводить лишь нужные SHA/несовпадения.

Изолированные черновики можно делать независимо только при явно назначенном владельце каждого файла.

## Формат отчёта по каждому ТЗ

1. Что изменилось для пользователя и какие пункты ТЗ выполнены.
2. Исходный и итоговый HEAD, список своих файлов, состояние оставшихся чужих изменений.
3. Миграции/изменения протокола, обратная совместимость и флаги включения.
4. Точные команды/логи тестов; отдельно выполненные, переиспользованные, пропущенные и не запущенные проверки.
5. Для денег — ID операции и сверка серверного журнала без токенов/личных данных. Для UI — сценарий и подтверждение состояния сервера.
6. Известные ограничения и конкретный следующий шаг. Не скрывать дефекты за «готово».
7. Для передачи следующему агенту — краткий `HANDOFF.md` и SHA затронутых файлов. Не пересылать ему всю историю диалога вместо этой сводки.

## Где нужен дополнительный review

Простые экраны, локализация и тестовые сценарии подходят для небольших поручений. Перед объединением отдельно проверить: атомарность денег, защиту повторов и смены аккаунта, численный турнирный рейтинг, Play-возвраты, миграции непустой базы. Нельзя заменять эти проверки уверенностью исполнителя или числом написанных тестов.
