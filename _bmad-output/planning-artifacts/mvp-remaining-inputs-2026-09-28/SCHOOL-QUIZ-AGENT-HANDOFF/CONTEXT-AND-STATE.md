## Изменения, перенос и возврат

До редактирования записать HEAD, dirty paths и SHA своих файлов; после — проверить серверные байты. Не `git add .`, не reset/checkout/clean, не рекурсивные chmod/chown. Коммитить только проверенный список своих файлов. Нужен отдельный лог на каждый повтор проверки; не затирать красные логи зелёными.

Локальный rsync — openrsync с совместимостью 2.6: трюк `-R ..././...` уже привёл к неверному пути. Для точечного переноса использовать cwd зеркала + точные относительные пути и `-rt -R`, затем проверить каждый SHA на сервере. Не `-a`, не `--delete`, не синхронизация всего дерева. При дрейфе preimage не заменять файл целиком: сначала понять изменения.

Schema 13 — последняя фактически проверенная на устройстве, но перед новой миграцией заново проверить текущую схему/экспорт. Только добавочные миграции, без destructive fallback. Старые попытки не превращать в новые серверно подтверждённые результаты.

Для каждого законченного среза: совместимый контракт → тесты → ограниченное включение на стенде. Отключение UI новых продаж не отключает обработку уже оплаченного/возвратов. Никаких публикаций, deploy в production, push/переноса в KMP или удаления старого сервера до соответствующего подтверждения владельца.
