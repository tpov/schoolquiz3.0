# ТЗ-06. Замкнуть продвижение отдельного урока

Зависимость: ТЗ-00; сквозное прохождение/оценка — после ТЗ-05. Результат: автор создаёт урок, независимые участники проверяют, куратор размещает его на Арене и продвигает дальше; история и выплаты видны и подтверждаются сервером.

## Что уже есть — не переписывать

Серверные `arena-service`, `arena-policy`, `arena-tickets`, каталог и `index.js` уже реализуют значительную часть правил. Есть callables `setLessonPlacement`, `rateArenaLesson`, `finalizeArenaSeason`; реальные тесты проверяли независимые проверки/кураторский допуск, замену оценки, одноразовые Турнир/Home-награды. Авторская выплата уже входит в расчёт ticket.

Raw `lesson_placements` и history закрыты rules, включая прямой доступ привилегированного клиента. Это защита, а не повод открыть коллекцию, чтобы заработал экран. Библиотека курсов/старый authoring уже существуют, но полный новый путь через UI не проверен.

## Этап A — данные и право доступа

- Составить короткую карту фактического вертикального пути: создание/редактирование → версия урока → отправка на проверку → независимые решения → размещение → чтение истории. Для каждого шага указать существующий порт или конкретный пробел; реализовать пробелы, не второй параллельный lifecycle.
- Создать недостающие typed lesson placement/rating/history DTO и owner/curator-safe read endpoints с ограниченными страницами/полями. Авторитетный UID/роль брать из Auth/серверных ролей, не payload/рейтинга.
- Сохранить причины отказа/жалобы и историю переходов. Public view, owner view и curator view разделить. Не выдавать приватные review-данные/ключи вопросов всем авторизованным.
- Старый quest-level рейтинг не копировать всем дочерним урокам. Legacy данные показывать как legacy/нет нового подтверждения; миграция без новых наград и выдуманных прохождений.
- Редактирование не меняет банк уже выданного ticket/созданного события. Допуск новой версии согласовать с действующей проверкой; нельзя незаметно заменить проверенные вопросы на непроверенные.

## Этап B — экран автора и куратора

- В существующем authoring добавить статус **конкретного урока**, причины/историю и допустимые действия. Курс остаётся в архиве.
- У куратора — просмотр доказательств проверок и явное подтверждение перехода/снятия с причиной. Хороший рейтинг/сезонная победа не заменяют это действие.
- Один mutationId на подтверждённое действие; repeated tap/потеря ответа — прежняя операция. Pending не отображается окончательно опубликованным без authoritative результата.
- После подтверждённого Arena-прохождения — оценка 1–3 через lesson-rating путь. Запрет самооценки и отсутствие права оценивать без receipt не только в UI, но и на сервере.
- Автор видит свою долю/историю выплат из журнала, а не локальный пересчёт всех показанных карточек. Награда за этап не начисляется повторно после снятия/возврата.

## Этап C — рейтинг, цена, сезон

- Проверить всё из PRODUCT-CONTRACT: weighted score, единичные/пустые рейтинги, равенства, линейные цены 1–100, одна текущая оценка, quarter UTC и tie-break.
- Открытый пробел: каталог и подготовка сейчас используют согласованную, но ограниченную ценовую совокупность, куда могут попасть устаревшие/недопущенные размещения. Если исправляется eligibility, изменить **вместе** catalogue/quote и prepare/server rank inputs. Уже выданные tickets не переоценивать.
- Каталог сейчас имеет технические пределы 1000 raw records/12000 reads. Не выдавать усечённую выборку за полный глобальный рейтинг/победителя. При росте данных нужен bounded durable расчёт/версионированный snapshot; нельзя просто убрать защиту без измерений.
- Сезонная операция запускается авторизованным серверным способом, использует серверное время и один ID сезона. Повтор/два worker-а не создают второй приз. Нет подходящих уроков — зафиксированный no-award, не случайный победитель.

## Проверки

Unit + настоящий Firebase: автор не проверяет сам себя; недостаточные/отозванные проверки; чужая роль; direct raw GET/PATCH/DELETE denied; восстановление истории без утечки; retries мутации; editing после admission; смена аккаунта; migration без synthetic ratings.

Расчёты: 20 разных прошедших против 19; заменённая оценка не новый голос; равные рейтинги/цены; квартал на UTC-границе; двойной finalize; milestone 15/20 один раз; сезон 10 один раз; цена 1 на пяти принятых оплатах даёт суммарно 4 нолика автору без потери дробей, если до них остаток был нулевой; цена 100 даёт 80.

Maestro с отдельными автором/проверяющими/куратором: создать → проверить → Арена → пройти/оценить → выплатить → продвинуть в Турнир → Home. Сверить lessonId/version, receipt, placement history и reward IDs на сервере. Нельзя закрыть тест административной записью готовых статусов вместо пользовательских шагов.

Приёмка: путь виден и работает через приложение, курс не переезжает, права и награды защищены сервером. Изменения цены/season отдельно reviewed перед включением.
