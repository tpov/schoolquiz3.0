# ТЗ-09. Витрина, premium, коробки и восстановление покупок

Зависимость: ТЗ-00; показ кошелька согласовать с ТЗ-02; возвраты принимать вместе с ТЗ-10. Результат — согласованная пользовательская витрина и устойчивые покупки, а не новые чистые ядра поверх старых.

## Что существует

На сервере подключены `box-service`, `gift-boxes`, `premium-grants`, `premium-economy`, `purchase-*`, `applyShopPurchase`, `verifyPurchase`, `submitGiftBoxOperation` и RTDN handler. На клиенте есть durable box intent/очередь и обычная магазинная структура. `GetShopCatalogUseCase` содержит старый ассортимент, а не завершённый новый набор 10/60/150 + premium 1/7/30/365.

На изолированном MVP реальные Play-продажи выключены, конфигурация продуктов пуста. SKU/прайс/настройки настоящего магазина не подтверждены. Redroid без Play/GMS не доказывает реальные покупки.

## Срез A — витрина и premium-представление

- Сохранить существующие полезные товары/навигацию, заменить только противоречащие новому контракту позиции. Золото 10/60/150; premium 1/7/30/365 дней за золото и Play.
- Premium за золото: сумма/период из серверных constants/catalog, server-validation каждого purchase; не произвольная цена от клиента. Play цена/валюта/доступность из ProductDetails/актуального Play-контракта, не hardcode.
- Отсутствующий SKU/цена → unavailable с причиной, а не выдуманная цена или успешная заглушка. Окончательные IDs/цены/аккаунт магазина при отсутствии получить у владельца; не выпускать с placeholders.
- Состояния premium: активен, закончился, неизвестна свежесть, pending purchase/refund. Ник/восстановление привязаны к действующим grants, не вечному boolean. Граница срока проверяется строго.
- Обычные и plasma ×2 рассчитывает сервер с реальными интервалами premium и сохранёнными остатками времени. Клиентский countdown — представление, не авторитетное начисление.
- RU/UK/EN, понятные длительности и способы оплаты, защита повторного tap.

## Срез B — коробки и серия

- Один тип коробки и общий баланс. Обычная ежедневная — максимум одна в день по серии; premium даёт отдельную ежедневную без рекламы. Не добавлять рекламный путь и не ограничивать остальные разрешённые источники.
- Offline streak использует существующие правила/устойчивые события и античит-ограничения; timezone/перевод часов/повтор/10 дней без сети не превращаются в безусловно доказанные посещения.
- Открытие только онлайн, через сохранённый original intent и server receipt. Двойное нажатие, response loss, restart — тот же результат открытия, не новая награда/списание.
- Pending animation может быть показана, но баланс/награда подтверждаются сервером. Другой аккаунт не получает старую покупку/коробку.

## Срез C — Play и восстановление

- Интегрировать текущую поддерживаемую Billing API по официальной документации **на момент исполнения**. Не обновлять библиотеку/target одновременно с переработкой всех денег без отдельного dependency-среза.
- Созданная/ожидающая/подтверждённая/отклонённая/неизвестная покупка различаются. PENDING и неподтверждённый token не выдают золото/premium.
- purchaseToken/operation identity устойчивы к reconnect и process death; обработка callback идемпотентна. Привязка к правильному app account проверяется сервером; recovery на другом UID не присваивает покупку.
- Query/recovery уже оплаченного работают при отключённой витрине новых продаж. ACK/consume выполняются согласно типу продукта и подтверждённому состоянию, с повтором после потери ответа; не признать операция завершённой только по локальному callback.
- Не печатать токены, order IDs/личные данные в общих логах. Для доказательств — redacted identifiers/hash и журнал.
- Разделить fake billing/unit-интеграцию и настоящую Play sandbox проверку. Не включать настоящие продажи/не оплачивать реальные товары без отдельного согласия.

## Приёмка

Unit/server: граница premium, пересечение нескольких grants, gold purchases, обе регенерации/holds, одна обычная+одна premium daily, offline duplicate, повтор opening и purchase, partial-use refund своего grant без других.

UI/Maestro demo: корректные недоступные Play-позиции, покупка premium за тестовое золото, открытие и восстановление box-intent, expiry, restart, account switch; сверка ledger/grants.

Play sandbox на подходящем устройстве: удачная/PENDING/отменённая операция, loss после server grant до ACK, recovery после restart, другой аккаунт, возврат после частичного использования. Если телефонов/тестового Play-набора нет — оформить blocker **этой приёмки**, не имитировать её Redroid-результатом. Остальные code/unit/UI части могут завершиться отдельно.
