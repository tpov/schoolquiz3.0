# 8.3/8.4 план адаптации формы приватных квизов (сессия 2026-10-21, reconnaissance)

Категория засеяна (private-quizzes-v1-catalog), доставка приватных квестов в клиент есть
(QuestPrivateRemoteDataSource/Sync — снимки {serverRevision, request}), но АВТОРСКОЙ половины
(настройки AD-29 в форме и payload подачи) в дереве нет — grep attemptLimit/showResult/expiry
пуст. План по слоям, порядок = порядок сборки:

1. domain (quest-authoring): PrivateQuizSettings {attemptLimit >=1 (default 1), showResult
   (default false), linkExpiresAtMs? (null = без срока)} + валидация AD-29 (лимит целый >=1,
   expiry только в будущее либо null); sunk в draft-модель приватного квеста.
2. data: перенос настроек в payload подачи (SUBMIT_ARENA-класс запрос приватного квеста) +
   серверный обработчик: сохранить settings в private/{uid}/quests/{questId}, start-гейт
   атомарно проверяет enabled/expiry/startedCount<limit (AD-29) — functions + node-тесты.
3. presentation (форма «Створення квесту» в категории «Приватные квизы»): скрыть
   Розділ/Тема/Урок-иерархию (плоский HARD-набор), показать attempt-limit (число >=1),
   show-result (переключатель), expiry (дата или «без срока»); дефолты AD-29;
   загрузка существующего квиза сохраняет настройки.
4. runner (8.4): attempt-limit расход при старте, show-result гейтит проекцию результата,
   statistics для автора — по EXAM/AD-31 контрактам.
5. Device-пруф 8.3 (Samsung, категория засеяна): форма адаптирована, дефолты верны, перезагрузка
   сохраняет настройки; 8.4 — запуск по ссылке, лимит, show-result на участнике.

Оценка: п.1-2 смена, п.3 смена, п.4-5 смена. Device: Samsung (.mvp) — подключить.
