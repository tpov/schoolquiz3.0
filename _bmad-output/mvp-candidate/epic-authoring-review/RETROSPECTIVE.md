### Diff-scope review (re-checked lens findings)

- **L1 [fix-now, HIGH] The lifecycle parser still refuses the integer forms its own epic proved real** — `636b1212` fixed `schemaVersion` coercion (LessonLifecycleWireParser.kt:77 `as? Number`) after the live 4.3 run showed the Android callable SDK delivering JSON numbers not as Long, and `InboxWireParser.requiredLong` (:84-88) uses the same coercion with a comment naming the family convention — but `requiredLong`/`optionalLong`/`unsigned` (:200-235) still exhaustively match `is Long/is Int`. A receipt whose `decidedAtMs`/`contentVersion`/`placementVersion`/rating fields arrive in a non-Long integer form throws after the server has applied the transition; the curator sees a transport failure and the retry path (L7) mints a new key. LessonLifecycleWireParserTest (+269) pins Long-shaped wires only — the documented hazard is unpinned.
- **L2 [fix-now, HIGH] Deploy-time regression for in-flight lessons: pre-4.6 TESTING records flip to not-tested** — `rebuildAggregate` now demands `stagePassed(testing) && (questionOutcomes.length === 0 || every passed)` (index.js hunk :5599-5606); `testingQuestionOutcomes` reads `record.questionScores`, which `normalizeReviewRecord` backfills to `[]` for legacy records (:6389-6393). A lesson already through TESTING before this deploy (score present, no per-question scores) on a question-bearing task gets `isTested: false` with `{testingScore: null, passed: false}` for every question at the next aggregate rebuild — it can never publish without a brand-new TESTING pass or a paid resubmission. No test covers legacy records (testing-review-threshold.test.js always writes questionScores; the suites were read).
- **L3 [fix-now, HIGH] Review-fee wallet writes skip the `nolics` mirror the rest of the money code maintains** — pre-existing paths dual-write both fields with a comment naming two live readers (index.js:4561-4562 «Both fields: FirebaseUserStatsDataSource reads pointsNolics and the economy data source reads…»); the fee reader itself falls back to `nolics` (:5890 `nonNegativeInteger(userData.pointsNolics, numberValue(userData.nolics, 0))`). But the charge writes only `pointsNolics` (:5913-5916) and the settlement credit only `pointsNolics` (:6055). After a charge the mirror shows pre-charge money; after a settlement it misses the reward — any `nolics` reader diverges from the ledger.
- **L4 [fix-now, HIGH] The initial-vs-recheck tariff is decided by an unvalidated client-supplied id** — `planReviewFeeCharge` keys `priorCycle` on `review_fee_quests/{request.draft.id}` and `quests/{request.draft.id}` existence with no `ownerUid` comparison (:5879-5887), and `review_fee_quests` is keyed globally by quest id. A hostile submission can name another author's quest id: pay 100×N instead of 1000 (N<10 is cheaper) and write its cycle counter onto a foreign fee document. The honest client path cannot collide (fresh generated draft ids) — the boundary is the receiver's.
- **L5 [fix-now] Error-report replay trusts the document without checking who filed it** — `applyLessonErrorReport`'s existing-document branch returns the stored result unconditionally (:2508-2512; no `stored.reporterUid === uid`, no `stored.lessonId === lessonId`), and `reportId` is client-chosen (`/^[A-Za-z0-9_-]{1,128}$/`). Whoever registers an id first owns its content; a colliding honest report replays the squatter's document and the app shows success while the real report is never delivered. (The inbox view's author-only readership holds — the harm is substitution/denial at submission time.)
- **L6 [fix-now, corrected framing] The knob named `testingPassScore` also governs LOGIC** — pre-epic `stagePassed` applied one constant to both stages; the epic made it configurable under a TESTING-specific name while `lessonPassed` and `failedReviewStages` keep applying it to LOGIC (hunks :5706-5710, :6298-6314). Raising the bar mid-cycle re-fails already-accepted LOGIC scores at the next rebuild (recorded `appliedConfigRevision` stamps the change; nothing re-scores). Either gate the knob to TESTING or rename/add a separate `logicPassScore` — an owner-visible semantic choice.
- **L7 [fix-now] A failed curator transition loses its idempotency key** — `DefaultCuratorComponent.onTransitionClick` clears `pendingTransition = null` unconditionally after `transitionLesson` returns, before the result fold (DefaultCuratorComponent.kt:129-131); the retry click then mints a fresh `idProvider.nextId` (:112-117). This contradicts TransitionLessonUseCase's recorded AD-2 contract (retry of an unknown-outcome transition must answer the same receipt), and the failed-transition test (DefaultCuratorComponentTest:221-235) asserts page state but never the key. Consequence after server-side INVALID_TRANSITION refusing the second decision: a timed-out-but-applied transition can only be recovered by leaving the screen; the same-receipt promise is unreachable from this UI.
- **L8 [fix-now] Editor history violates its own unit contract on every keystroke and every no-op** — `updateEditable` pushes the prior snapshot per call (DefaultQuestCreateComponent.kt:1183-1190 in the diff), so per-keystroke text edits are one history step each (limit 100 ≈ the last 100 keystrokes), and guard-guarded no-op calls (option add at MAX_EDITOR_ROWS, remove at MIN) push before returning the state unchanged — the first undo after a no-op appears to do nothing. The interface doc claims «одна правка — один шаг истории» (QuestCreateComponent.kt:1183-1189). Push only on actual change; debounce or commit text on focus loss.
- **L9 [fix-now] Legacy segment results are laundered into explicit decisions on read** — `normalizeReviewRecord` backfills `decision: stringValue(item.decision, item.accepted ? "correct" : "error")` (index.js:8283) while the same epic's contract refuses silent approvals at the receiver («молчаливое одобрение… запрещено», silent accepted → 400). Old `accepted:true` rows read as explicit «correct» decisions in stored documents and any future export — the audit trail cannot distinguish reviewed work from pre-contract guesses. Keep legacy rows decision-less (or flag them) instead of backfilling.
- **L10 [fix-now] The transition endpoint lacks the reason byte-bound its client claims to mirror** — `transitionLesson` validates `text(reason, "reason")` only (arena-service.js:261), while `rejectReviewSubmission` enforces `MAX_AUTHOR_REJECTION_REASON_BYTES` (index.js:1482) and the client caps at 1000 bytes citing the server ceiling (TransitionLessonUseCase.kt:24-33). Non-app clients can write megabyte reasons into `lastReason`/history that every future lifecycle page carries.
- **L11 [fix-now, small, out-of-diff] A duplicate-question guard that cannot fire** — `unavailable(seen.add(outcome.questionId))` (arena-lifecycle-views.js:255-257): `Set.add` returns the Set (always truthy), so the intended rejection of repeated questionIds in the review-outcomes projection never triggers. Discovered by the adversarial lens but **pre-existing epic-3 surface, not in this epic's diff** — carried here as a retro-discovered defect, not an epic finding.
- **L12 [defer/owner question] Translation self-review after a level gap** — neither `canSubmit`/`translationTargets` (index.js:7275-7352: level-gap + known-language filters only) nor the paid path (`buildReviewUnits`, review-fee.js:11188 drops only the lesson owner) excludes the translator of language L from segment-reviewing that same translation once their translatorLevel clears the recorded level by `TRANSLATION_REVIEW_LEVEL_GAP`. Level distance may be the intended independence mechanism for translations (it is the only one implemented) — the owner decides; conservation itself is unaffected.
- **L13 [defer] Inbox projection truncates silently at two caps** — `maxOwnedLessons: 25` taken in `__name__` order (an arbitrary stable subset of the author's placements) and `commentsPerLesson: 10` with no ordering (lexicographically first 10 once a lesson exceeds it), with a clean `nextAnchor: null` that reads as end-of-list (inbox-views.js:171-188). The in-code comment names the boundary honestly; the consumer still cannot distinguish truncated from complete. Popular lessons/authors quietly stop seeing inbox items.
